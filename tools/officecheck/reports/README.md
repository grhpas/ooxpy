## Findings

- **Office 2007 accepts everything oox writes in the corpus**, including Office 2010 (w14) markup declared `mc:Ignorable`, edited Word- and PowerPoint-authored files, pictures in all four formats, and placeholders. Every content probe matched, including formulas calculated by Excel.
- **Word's view of sections, headers, notes and fields matches oox's readers.** The step 3 probes run twice, through COM in Word 2007 and through oox's readers on LibreOffice's re-save, and agree in both. That includes "Link to Previous": section 2's footer, which oox doesn't write, shows section 1's page-number fields in Word.
- **Word doesn't count a table row made only of vertical-merge continuations.** `word-15-tables` table 2 has 4 `w:tr`; the third consists of cells continuing "Group A" and "X". Word 2007: `Rows.Count` = 3, while cell counts (14 and 6) and cell texts match oox exactly. LibreOffice shows the row as a thin line, so layout differs between the two. oox now offers `Table.word_row_count`, and the docs advise against merges that cover a whole row.
- **Word 2007 can't tell "behind text" from "in front of text" through COM.** Both read as `WrapFormat.Type` 3 (wdWrapNone). The file says `behindDoc="1"`, and LibreOffice draws it behind. Newer Word has a separate value (wdWrapBehind, 5): **Word 2016 confirmed it** (`word-16`: behind, square, tight). The checker now reports "none" on Word 2007 and compares accordingly.
- **Excel built-in number formats 14–22 and 37–40 are regional.** A cell with `numFmtId="40"` (`#,##0.00;[Red](#,##0.00)` in ECMA-376) showed `-98,25` instead of `(98.25)` in Greek Excel 2007. oox now writes such codes as custom formats (ids from 164) and maps only the locale-invariant ids (0–4, 9–13, 45–49).
- **`Range.Text` follows the regional settings**: decimal and thousands separators (`1.234,50`) and month/day/AM-PM names (`14 Νοεμβρίου 2026`, `Σάββατο`, `3:07 μμ`) are Greek. A `[$-409]` prefix in the code forces English names on any machine (`excel-11`). Through pywin32 (which passes the user's locale to COM), Excel also answers `NumberFormat` and validation lists in the regional variant (`0,0%`, `Yes;No`). Even format-code letters are translated (`yyyy-mm-dd` → `εεεε-μμ-ηη`). The checker now reads such properties with LCID 1033, swaps separators only for plain numbers (in dates, `,` and `.` are literal text), and judges name probes only when the *regional setting* (`xlCountrySetting`) is English; Excel's own language (`xlCountryCode`) was English here. In a custom code, `AM/PM` came out as "PM" even on Greek settings.
- **Dates in default-width columns show `########`**: "2026-11-14" doesn't fit Excel's 8.43-character column. oox now has `autofit_columns()`.
- **Excel 2007 misreports the type of plain conditional-format rules through COM.** `FormatCondition.Type` raises 0x800A03EC when the rule comes from `Worksheet.Cells.FormatConditions`, and when it comes from a cell's `FormatConditions` it returns the type of that cell's first rule: the formula rule (priority 9) read as "cellIs" in B2, "colorScale" in C2, "dataBar" in D2. Everything else reads correctly: counts, `Priority`, `AppliesTo`, and the special rule classes, which are told apart by their COM interface (ColorScale, Databar, IconSetCondition, Top10, UniqueValues, AboveAverage). So the files are right and the property is wrong. Two lessons for the kit: a silent fallback hid the first error for one round, and the report now shows every COM step of a traced probe. On Excel < 14 the checker counts plain rules (comparison, formula, text, blanks) as one group, says so in the report, and only traces a kind derived from Operator/Formula1/TextOperator/Text; newer Excel is judged on `Type` in full. LibreOffice already confirms every rule's type (`check_libreoffice.py`). Through the sheet's rules, Excel 2007 also refuses `Operator`, `Formula1`, `TextOperator` and `Text` of plain rules, except `TextOperator`/`Text` on the text rule (contains "South"), so only the comparison and formula rules remain unconfirmed by COM. The `excel.screenshot` picture confirms them, and shows Excel combining non-conflicting formats from several rules (bold from top 2 under the >95 colours; blue from duplicates with italic from the text rule), which LibreOffice doesn't.
- **`Range.CopyPicture` as a bitmap renders text badly** (no smoothing: text on white looks bold, coloured fringes), so a bitmap screenshot can't judge bold except between cells with the same fill. The probe captures as a metafile (`xlPicture`) at 2x first.
- **PowerPoint 2007 draws no picture without a geometry.** A picture placeholder filled with `<p:spPr/>` inherits its shape from the layout and master; oox's skeleton (like some templates) has no `a:prstGeom` there, and PowerPoint 2007 then shows nothing, while LibreOffice assumes a rectangle. `set_placeholder_picture` now writes `prstGeom rect` when nothing would provide one. Only a screenshot showed this: the probe (`PlaceholderFormat.ContainedType`) doesn't exist in PowerPoint 2007, so it now falls back to `PictureFormat` crop values there.
- **Word 2007 opens ISO values the SDK rejects** (`word-94`): `w:lvlJc` and table `w:jc` "start", `w:cantSplit`/`w:tblHeader` "true", as LibreOffice writes them. oox accepts them now (`grammar.EXTRA_ENUM_VALUES`). It also tolerates LibreOffice's out-of-order numbering level and duplicate run properties (`word-95`), like the earlier order case; those stay validation findings because the schema forbids them.
- **PowerPoint 2007's `Slide.Hyperlinks` misses text-run links.** On `ppt-10` it returned two entries for a slide with two text links, a slide-jump shape and a show-jump shape: the show jump (SubAddress "-1,-1,NEXT") and the slide jump ("258,3, "); neither text link. The text links are in the file and work (blue and underlined in the slide image, and python-pptx and LibreOffice read them). The probe now asks each shape's and each text run's `ActionSettings` instead. `ppt-11`, with a single text link in a title, was listed correctly, so the collection is unreliable rather than empty.
- **Parameterised COM properties fail through dynamic dispatch**: pywin32 fetches `Chart.HasAxis` without its arguments, and Excel 2007 answers E_FAIL, on a chart whose secondary axis is visible in its own export. `Axes.Item` is also not positional: it takes (Type, AxisGroup), so walking `Item(1..Count)` asks for axes that don't exist. Methods with arguments (`Chart.Axes(2, 2)`) are fine.
- **Word answers a wrong `Unprotect` password with a dialog as well as a COM error.** Word 2007 showed "The password is incorrect" (an OK box, closed by the watchdog) and raised error 0x800A1595 from the same call; Excel's `Workbook.Unprotect` only raised. A probe that tests refusal therefore provokes a dialog on purpose. Matching the dialog's text would break on localized Office, so the checker attributes by time: dialogs shown during the wrong attempt (plus 2 s) go to `expected_dialogs`, shown in the report and not counted. Word 2007 also checks SHA-512 password hashes (`cryptAlgorithmSid` 14, `rsaAES`), so oox's SHA-1 default is a choice for older readers rather than a 2007 requirement.
- **An unactivated Office looks like a broken file unless the checker knows better.** Office 2016 without an activated licence showed "Sign in to set up Office" while opening most Word and Excel files (not PowerPoint), and in reduced functionality mode refused calls that change the document or read layout (`Unprotect`, `AcceptAll`, `ParagraphFormat`, `WrapFormat.Type`, `Range.CopyPicture`) with "... not available because the licence to use this application has expired". Reading text, tables, fields, charts, conditional formats and properties still worked. While the sign-in dialog was up, Word also answered "Call was rejected by callee" (RPC_E_CALL_REJECTED). The checker now moves account/activation dialogs to `environment_dialogs`, marks licence refusals `refused` (neither counts; status 🔒 "unactivated" when probes were refused) and retries rejected calls. The licence test matches English text; a localized unactivated Office would still show ⚠️, with the dialog title in the details.
- **Excel 2016's `FormatCondition.Type` is right** where Excel 2007's wasn't: every plain rule reads as its own type (cellIs, expression, containsText …) through the sheet's rules.
- **Kit bug: reruns overwrote earlier result files.** `check_office.py` wrote `results-<host>-<versions>.json` on every run, so `--only` reruns replaced each other (and any full run on that machine). Each run now writes its own file with a date and time, and `report.py` merges them. `--only` takes several cases (`word-15,word-16`).
- **PowerPoint hides prompts under automation** (`DisplayAlerts` defaults to `ppAlertsNone`). The first control run missed the PowerPoint control for that reason. The checker now turns alerts on in all apps.
- **PowerPoint 2007 repairs a corrupted slide by blanking it**, after an OK-only notice ("Affected slides have been replaced by blank slides"). The control's probe confirmed the content was lost, so with alerts off this would have been a silent repair.

## How strict is Office 2007? (observe cases, 2026-11-14)

| Schema problem (one per file) | Office 2007 | Consequence for oox |
|---|---|---|
| Word: `w:pPr` / `w:rPr` children out of order | opened, no prompt | tolerated; oox still writes schema order (correct, cheap, other versions may differ) |
| Word: unknown element in the `w:` namespace | opened, no prompt | tolerated |
| Word: invalid attribute values (`w:jc="middle"`, `w:color="red"`) | **refused** ("Command failed" after a prompt) | lexical validation is essential for Word |
| Excel: rows out of ascending order | **refused to open** | the row-order semantic rule is essential |
| Excel: Office 2010 attribute (`workbookPr/@dateCompatibility`) in the 2007 namespace | **refused to open** | version targeting predicts real breakage: LibreOffice-written .xlsx files don't open in Excel 2007; check with `validate(target="Office2007")` |
| PowerPoint: required `p:grpSpPr` missing | prompt; slide replaced by a blank one | required-children checks are essential (content is lost) |

Each fatal row corresponds to a `validate()` finding oox already reports. The
two tolerated rows (order, unknown elements) remain findings, because the
specification requires them.
